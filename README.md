# Alfa News Insights

Прототип для Альфа-Будущее Хакатона, трек «Новостная аналитика для принятия бизнес-решений».

Сервис собирает новости из открытых источников, отбирает те, что важны конкретной компании,
и с помощью агента на LLM объясняет, что событие значит для её бизнеса. Объяснение учитывает
признаки компании и аналитику Альфа-Банка. Факты, позиция банка и выводы AI в ответе разделены.

## Архитектура

```
RSS-источники ──► парсер ──► склейка дублей ──► классификация (правила) ──► PostgreSQL
CSV кейса ──► профиль компании (признаки, доля рынка, контрагенты, interests) ──► PostgreSQL
Аналитика Альфа-Банка (pdf/txt) ──► чанки ──► поиск BM25 (RAG)

Лента компании = новости × interests компании ──► ранжирование с причинами отбора
Инсайт = агент: план → инструменты → черновик → самопроверка (правила + критик) → повтор → JSON + трасса
```

| Компонент | Файл | Что делает |
|---|---|---|
| Парсер новостей | `app/news/rss.py`, `ingest.py` | RSS/Atom, очистка, склейка одного события из разных источников |
| Классификация | `app/news/classify.py` | Темы, отрасли, страны правилами, без затрат на LLM |
| Профиль компании | `app/companies/profile.py` | Продукты, ВЭД, отрасль по ОКВЭД, доля рынка, контрагенты по платежам, связи через физлиц |
| Ранжирование | `app/ranking.py` | Сопоставление новости с интересами компании, у каждого совпадения сохраняется причина |
| RAG | `app/analytics.py` | Поиск по материалам Альфа-Банка |
| Агент | `app/agent/runner.py` | Многошаговый процесс, трасса каждого шага |
| Самопроверка | `app/agent/validate.py` | У каждого факта и вывода должна быть ссылка на реальный источник или признак |
| Инструменты | `app/agent/tools.py` | Белый список, только чтение, журнал вызовов |
| LLM | `app/llm/client.py` | OpenAI-совместимый API, кэш, журнал, защита дневного лимита |

## Запуск

Нужны Docker и Docker Compose.

```bash
cp .env.example .env          # заполнить LLM_BASE_URL и LLM_API_KEY
# положить данные кейса в ./data (см. ниже); без них загрузятся синтетические примеры
docker compose up --build
```

API: http://localhost:8000, Swagger: http://localhost:8000/docs

### Данные

| Файл | Куда положить | Переменная |
|---|---|---|
| Компании `df_Uid_data_hack.csv` | `data/` | `COMPANIES_CSV` |
| Физлица | `data/` | `PERSONS_CSV` |
| Платежи | `data/payments.csv` | `PAYMENTS_CSV` |
| Аналитика Альфа-Банка (pdf/txt/md) | `data/alfa_analytics/` | `ALFA_ANALYTICS_DIR` |

Если реальных файлов нет, используются `data/sample_companies.csv` и `data/sample_payments.csv`
(синтетические данные для end-to-end проверки).
После замены данных: `POST /admin/load-companies` и `POST /admin/reload-analytics`.

### Переменные окружения

См. `.env.example`. Основные:
- `LLM_BASE_URL`, `LLM_BASE_URL_FALLBACK`, `LLM_API_KEY`: шлюз LLM организаторов (основной и запасной адрес) и ключ команды;
- `LLM_MODEL_FAST` (план, критик) и `LLM_MODEL_SMART` (интерпретация): только модели из списка кейса;
- `LLM_DAILY_TOKEN_LIMIT`: сервис перестаёт обращаться к LLM, когда дневной расход достигает этой суммы;
- `NEWS_INGEST_INTERVAL_MIN`: период фонового сбора новостей.

## Сценарий проверки

1. `GET /health`: компании загружены, видны документы аналитики. `POST /admin/llm-ping`: проверка доступа к моделям.
2. `POST /news/ingest`: собрать свежие новости.
3. `GET /companies`: список крупных компаний (выручка от 15 млрд ₽).
4. `GET /companies/DEMO_U_001`: профиль с признаками, долей рынка, контрагентами и интересами.
5. `GET /companies/DEMO_U_001/feed`: лента под компанию с причинами отбора (`why_selected`).
   Сравните с `GET /companies/DEMO_U_005/feed`: лента у другой компании другая.
6. `POST /companies/DEMO_U_001/insights` с `{"news_id": <id из ленты>, "role": "cfo"}`: персональный инсайт.
7. `GET /insights/{id}/trace`: как получен вывод (план, вызовы инструментов, самопроверка).
8. `POST /insights/{id}/ask` с `{"question": "Как это скажется на рефинансировании?"}`: уточняющий вопрос.

## Формат инсайта

`app/schemas.py::InsightPayload`:
- `facts`: подтверждённые факты, у каждого ссылка на источник (`N1` — новость, `N2…` — связанные новости);
- `bank_view`: позиция Альфа-Банка, у каждой ссылка на фрагмент аналитики (`A…`);
- `ai_inference`: выводы модели со ссылками на факты, позицию банка и признаки клиента;
- `client_features_used`: какие признаки компании повлияли на вывод;
- `risks`, `opportunities`, `actions`, `questions_to_check`, `bank_product_hint`, `relevance`, `horizon`;
- `sources`, `features`: расшифровка всех идентификаторов, нужна для трассируемости.

## Безопасность AI-компонента

- Новости и аналитика попадают в промпт как данные в тегах. Модели прямо запрещено выполнять инструкции из них (защита от prompt injection).
- У агента только инструменты на чтение из белого списка. Каждый вызов пишется в `tool_calls`, вызов вне списка блокируется и тоже журналируется.
- Агент видит данные только той компании, для которой строит инсайт.
- Все обращения к LLM журналируются в `llm_calls`. Действует дневной лимит токенов.
- Данные кейса обезличены. Ключи хранятся только в `.env`, в git его нет.

## Качество и мониторинг (предложение)

- Доля выводов, прошедших самопроверку без замечаний (`insights.status = ok`).
- Precision@5 ленты по экспертной разметке на выборке компаний.
- Доля инсайтов, где использована аналитика банка (`bank_view` не пуст).
- Оценки пользователей 👍/👎 по каждому инсайту (запланировано).
- Расход токенов на инсайт и попадания в кэш (`llm_calls`).

## Масштабирование

- Новый источник новостей добавляется одной строкой в `app/news/sources.py`.
- Новая отрасль или тема добавляется словарём в `app/news/classify.py` и правилом в `build_interests`.
- Новые материалы банка достаточно положить в `data/alfa_analytics/` и вызвать `POST /admin/reload-analytics`.
- Поиск можно заменить на эмбеддинги в pgvector, не меняя интерфейс `AnalyticsIndex.search`.
